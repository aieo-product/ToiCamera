FEATURED — bring your own backend

Worker setup

ToiCamera never talks to OpenAI directly. The watch calls a small Cloudflare Worker that holds every API key, defines the model menu, picks the TTS voice and answers with strict JSON. You deploy it under your own free Cloudflare account — the whole system is yours. No shared backend, no third-party server.

⏱ Time budget: about 10 minutes. Everything runs on Cloudflare's free tier. You only pay OpenAI for what the watch actually asks.

🔧 Manual path, step by step

0

Prerequisites

  • A free Cloudflare account — the Workers free tier is plenty. Sign up with Google/Apple/GitHub or email:
  • An OpenAI API key — create one at platform.openai.com/api-keys (“Create new secret key”, copy the sk-… string somewhere safe)
  • Node.js 18+ on your PC — npx runs wrangler, no global install needed
1

Deploy the Worker

# in your clone of the repo
cd worker
npm install
npx wrangler deploy   # first run opens a browser → click “Allow” to log in

The deploy output prints your Worker URL — keep it, the firmware needs it in step 3:

Uploaded toicamera (2.59 sec)
Deployed toicamera triggers (0.91 sec)
  https://toicamera.<your-subdomain>.workers.dev
2

Set the secrets

The Worker reads three secrets (plus one optional). From the terminal — each command prompts on stdin, so keys never touch your shell history:

npx wrangler secret put OPENAI_FREE_API_KEY   # paste your OpenAI key
npx wrangler secret put OPENAI_API_KEY        # same key again (TTS)
npx wrangler secret put DEVICE_TOKEN          # a password YOU make up, e.g. `openssl rand -hex 16`
SecretWhat it is
OPENAI_FREE_API_KEYOpenAI key used for vision / Q&A / digest. Any OpenAI key works — the name comes from the author's free daily-token program
OPENAI_API_KEYOpenAI key used for TTS. Usually the same key as above
DEVICE_TOKENA shared secret you invent. The watch sends it as X-Device-Token; the Worker rejects everything else
ANTHROPIC_API_KEYOptional — only if you flip ANALYZE_PROVIDER to anthropic

Prefer clicking? The dashboard does the same thing: your Worker → Settings → Variables and Secrets → Add, choose type Secret:

3

Point the watch at your Worker

Two values connect the firmware to your Worker: the URL from step 1 and the device token from step 2.

  • At build time — put both in firmware/stopwatch/secrets.ini (copy from secrets.ini.example; gen-secrets.sh automates it): 
    -DWORKER_URL=\"https://toicamera.<your-subdomain>.workers.dev\"
-DDEVICE_TOKEN=\"<the token you made up>\"
  • Or at runtime — the token (not the URL) can be entered later from the watch itself: Settings → WiFi → scan the QR → http://192.168.4.1 → the device token field. Stored in NVS, overrides the build-time value. This field expects the DEVICE_TOKEN shared secret — not an OpenAI key.
4

Verify

curl -s "https://toicamera.<your-subdomain>.workers.dev/config" \
  -H "x-device-token: <your token>"

Expected:

{"models":["gpt-5.6-terra","gpt-5.6-luna"],"voice":"marin","tts":true}
ResponseMeaning
401Token mismatch — header value must equal the DEVICE_TOKEN secret
429 + reset_jstOpenAI free daily quota exhausted; the watch shows the reset time
400 empty or truncated image(on /analyze) the test file is smaller than 128 bytes

Watch live logs while testing from the device: npx wrangler tail — or in the dashboard, the Worker's Observability tab shows every request the watch makes:

🎛 Your Worker, your model menu

The watch never hardcodes model names: on boot it fetches GET /config and shows whatever your Worker offers in Settings → Model. The menu is one var in worker/wrangler.jsonc:

"MODELS": "gpt-5.6-terra,gpt-5.6-luna",   // comma-separated — this IS the Settings menu

Edit, npx wrangler deploy, reboot the watch — done. The same applies to the speech voice: the watch only chooses chirps or TTS; which voice TTS speaks with is your Worker's TTS_VOICE var.

🏠 Local LLM (Ollama, LM Studio, …)

Everything the Worker calls goes through the OpenAI-compatible OPENAI_BASE_URL var — so the “AI” can be a model running on your own machine:

  1. Run a local server with an OpenAI-compatible API — e.g. ollama serve (endpoint http://localhost:11434/v1)
  2. Expose it: cloudflared tunnel --url http://localhost:11434 → you get a public https://….trycloudflare.com host (or use a named tunnel on your own domain)
  3. Point the Worker at it and redeploy: 
    "OPENAI_BASE_URL": "https://<tunnel-host>/v1",
"MODELS": "gemma3:12b",          // whatever `ollama list` shows
"ANALYZE_MODEL": "gemma3:12b"    // default when the device sends none
Voice STT/TTS intentionally use a separate base (OPENAI_AUDIO_BASE_URL, default api.openai.com) — speech keeps working even while chat runs on a chat-only local server.
Pick a vision-capable model for /analyze (it receives a photo). Structured-output support (response_format: json_schema) varies by server; Ollama ≥ 0.5 handles it.

🔒 Security notes

  • API keys exist only as Worker secrets — never in the firmware, NVS or repo.
  • The device↔Worker link is HTTPS, but the firmware uses setInsecure() (no CA pinning). Fine for a hobby build that only sends a photo and a token; pin the root CA if you fork this for anything serious.
  • Change TOI_AP_PASS (watch AP password) before deploying your own — anyone who joins the watch AP can reach the setup portal.
